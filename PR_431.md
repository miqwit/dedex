# Add ERN 4.3.1 support

Adds parsing of DDEX ERN **4.3.1** (`http://ddex.net/xml/ern/431`) following the same approach as the other versions: entity classes generated by `xsd2php` from the official XSD, one `Ern431` namespace, version detected from the `xmlns:ern` of the file, `Simple*` entities and rules adapted.

Branch: `version-431` (three commits on top of `master`).

## 1. What 4.3.1 actually brings over 4.3 (in plain terms)

The full technical diff is in section 2. Here is what each change is *for*:

| Change | What it's for | Kind |
|---|---|---|
| `AdditionalTitle` → `FormalTitle` / `GroupingTitle` | 4.3's single `AdditionalTitle` used a `TitleType` attribute to mean either "the formal/legal title" (classical works, e.g. an opus number) or "the title of the series/collection this belongs to". Splitting it into two elements makes that distinction explicit and machine-readable instead of relying on the attribute value. | Clarity / modeling fix |
| `Genre` → `DisplayGenre` | Pure rename, no new data. Distinguishes the consumer-facing genre from other genre-like fields elsewhere in the standard. | Rename only |
| `Brand` in `PartyList` | Lets a sender declare a sub-label/imprint as a first-class party (with its own name and IDs), separate from the record company. Useful for major labels or distributors operating many imprints under one legal entity. | New capability |
| `ContainsAI`, `AiContribution`, `SpecialContributor="GenerativeAI"` | DDEX's answer to AI-generated/AI-assisted music: lets a sender disclose, at the release/resource/contributor level, whether and how generative AI was involved. This is what DSPs increasingly require for transparency and policy enforcement. | New capability |
| `SpecialContributor="Traditional"` / `"VariousArtists"` | Standardizes how to say "no single composer, this is a traditional/folk work" or "compilation, no single artist" without inventing a fake party. Mainly relevant to classical and compilation catalogs. | New capability |
| `Role` becomes a composite (`Value` + `InstrumentType`) | Lets a contributor credit carry which instrument they played (e.g. Role=AssociatedPerformer, Instrument=Guitar), not just the role name. Richer liner-note-level credits, useful for classical/orchestral releases. **This is also the one breaking change**: a 4.3 file's `<Role>Composer</Role>` is not valid 4.3.1 XML any more. | New capability + breaking shape change |
| `ParentalWarningType` optional, gains `ParentalWarningStandard` | 4.3 forced every Release/SoundRecording/Video to declare a parental warning even when none of the regional standards apply. 4.3.1 makes it optional and lets the sender say *which* standard (e.g. RIAA vs PAL) the value follows, instead of a single ambiguous flag. | Modeling fix |
| `DisplayCredits`, `SentAsRequestedBy`, `RightsClaimPolicyReason`, `SubGenreCategory/Description`, `ChapterId` | Smaller additions: free-text display credits per artist, an audit-trail field for messages sent on behalf of a third party, a reason code for automated rights claims, a description for classical sub-genres, and typed identifiers for chapters. | New capability (minor) |
| `…WithDefault`/`…WithType`/`…WithTerritory` types renamed to their short form (`CLine`, `PLine`, `AdministratingRecordCompany`, `PriceInformation`, …) | Schema cleanup, no functional change for you: same data, same XML shape (`PLine`/`CLine` additionally gain the optional `ApplicableTerritoryCode`/`IsDefault` attributes they were missing). | Rename / cleanup |

**Bottom line**: most of 4.3.1 is optional new data your parser will now expose if present (AI disclosure, brands, richer credits, chapters) plus two modeling fixes (title semantics, optional parental warning). The one thing that can silently break existing 4.3-shaped code is `Role` becoming a composite — see the "silent breakages" list in section 2.

## 2. What changed in ERN 4.3.1 (formal XSD diff vs the 4.3 XSD in the repo)

Source: <https://service.ddex.net/xml/ern/431/release-notification.xsd>, compared type by type (elements, attributes, cardinalities, patterns, enumerations) with `xsd/release_notification/43/release-notification.xsd`. Not compared: documentation text, `sequence` ordering and `xs:any`/`choice` details.

**Removed / renamed**
- `AdditionalTitle` removed everywhere (Release, SoundRecording, Image, Video, Text, SheetMusic, Software, Chapter, Cue, ResourceGroup, ResourceSubGroup, RelatedRelease, TrackRelease, ClipRelease). Replaced by optional, repeatable `FormalTitle` and `GroupingTitle` (type `DisplayTitle`).
- `Genre` renamed `DisplayGenre` on `Release`, `TrackRelease`, `ClipRelease` (same `GenreWithTerritory` type).
- "With…" types replaced by their short name: `CLine`, `PLine` (gains `ApplicableTerritoryCode`/`IsDefault`, loses `PLineType`), `CourtesyLine`, `FulfillmentDate`, `PriceInformation`, `AdministratingRecordCompany`.
- `DisplayArtistNameWithDefault` -> `DisplayArtistNameWithOriginalLanguage` (new attribute `IsInOriginalLanguage`).
- `ParentalWarningTypeWithTerritory` -> `ParentalWarningTypeWithStandard` (new attributes `ParentalWarningStandard`, ...). `ParentalWarningType` is now **optional** on Release, SoundRecording and Video.
- `ContributorRole` is now a composite: `<Role><Value>Composer</Value>[<InstrumentType>..</InstrumentType>]</Role>` (**breaking change of the XML shape** vs 4.3 where it was `<Role>Composer</Role>`).
- `Chapter` gets a dedicated `ChapterId` type.

**Added (all optional)**
- `Brand` in `PartyList` (so `PartyList` is no longer a plain array of `Party` in the generated classes).
- Generative AI: `ContainsAI` (Release, SoundRecording, Image, Text, Video; values `All`/`None`/`Partly`), `AiContribution` (Contributor, EditionContributor).
- `SpecialContributor` (Contributor, EditionContributor) and `SpecialDisplayArtist` (DisplayArtist), type `SpecialContributorType`: `GenerativeAI`, `Traditional`, `VariousArtists`, `UserDefined`.
- `DisplayCredits` on DisplayArtist, `SentAsRequestedBy` on MessageHeader, `RightsClaimPolicyReason` on RightsClaimPolicy, `Description` on SubGenreCategory.

**AVS**: the 4.3.1 XSD imports the remote `allowed-value-sets.xsd` (AvsVersionId 12). The repo's `avs43.xsd` is v11. Many additions (artist types, contributor roles, instruments, `VoiceType`, ...) and a few removals (`Duet`, `StrohlViolin`, `NewStudioRole`).

## 3. What this PR does

### Files added
- `xsd/release_notification/431/release-notification.xsd` — official XSD, only the `schemaLocation` of the AVS import points to the local file (offline validation).
- `xsd/release_notification/431/avs431.xsd` — AVS v12, unmodified.
- `config/xsd2php.yaml` — the generator config (was not versioned before), for 431.
- `src/Entity/Ern431/**` — **generated, do not review line by line**. 418 files (209 classes + JMS metadata). Regenerate with:
  ```
  ./vendor/goetas-webservices/xsd2php/bin/xsd2php convert config/xsd2php.yaml xsd/release_notification/431/release-notification.xsd
  ```
- `tests/samples/030..033_ern431_*.xml` (see section 4).

### Code changes (hand-written, the part to review)
| File | Change |
|---|---|
| `src/Controller/ErnParserController.php` | `"431"` added to `$supported_versions`; docblocks. Namespace regex `(\d+)` already yields `431`. The parser is reflection-driven, so renamed/new tags need no other change. |
| `src/Simplifiers/SimpleEntity.php` | `isVersion431OrLater()`; `getContributorRole()` (reads `Role->getValue()` when the role object has `getValue()`); `buildPartyIndex()` handles the `PartyList` composite (`->getParty()`). |
| `src/Simplifiers/SimpleAlbum.php` | `getGenre()`/`getSubGenre()` use `getDisplayGenre()` on 4.3.1 via `getGenreComposite()`. |
| `src/Rule/AllSoundRecordingsHaveIsrc.php` | 4.3.1 stores `ResourceId` in `SoundRecordingEdition` like 4.3. |
| `src/Rule/Rule.php` | default `$supported_versions` includes `"431"`. |
| README / CHANGELOG / CONTRIBUTE | version list, changelog, generation howto. |

### Silent breakages found and fixed (worth knowing)

These would have returned empty/null data **without any error** on a 4.3.1 file:
1. **Contributor roles**: `resolveContributors()` swallows `Throwable`; `getRole()[0]->value()` no longer exists on 4.3.1 so every contributor was silently dropped.
2. **PartyList**: `buildPartyIndex()` iterated `getPartyList()` as an array; on 4.3.1 it is an object -> no party names resolved.
3. **Genre**: `getGenre()` does not exist any more -> `null`.
4. **ISRC rule**: fatal `Call to undefined method SoundRecordingType::getResourceId()`.

9 new tests (suite: 56 tests, 820 assertions, all green). Run: `vendor/bin/phpunit`. Two PHPUnit warnings and one deprecation are printed; they are not from this change (and the `.phpunit.result.cache` permission warning depends on your environment).

Samples (all four are **valid against the 4.3.1 XSD**, checked with `DOMDocument::schemaValidate`, and parsed with `setXsdValidation(true)` in tests):
- `030_ern431_album.xml` — 018 (4.3 album) converted: namespace, `DisplayGenre`.
- `031_ern431_real_world_single.xml` — 019 converted, `Role/Value`. (Empty `PartyId` of the original fixed to be XSD-valid.)
- `032_ern431_classical.xml` — 028 converted: `AdditionalTitle[@TitleType=FormalTitle]` -> `FormalTitle`, 39 roles.
- `033_ern431_new_features.xml` — hand-made, exercises every element added or reshaped by 4.3.1 (formal diff in section 2), each on at least one composite: `SentAsRequestedBy` (MessageHeader), `Brand` (PartyList), `ChapterList`/`Chapter`/`ChapterId` (new top-level list), `FormalTitle`/`GroupingTitle` (Release + Image), `SpecialDisplayArtist` and `DisplayCredits` (DisplayArtist), `IsInOriginalLanguage` (DisplayArtistName), `AdministratingRecordCompany`, `PLine`/`CLine` with `ApplicableTerritoryCode`/`IsDefault`, `SubGenreCategory`/`Description` (DisplayGenre), `ContainsAI` (Release, SoundRecording, Image), `AiContribution`/`SpecialContributor` on both `Contributor` and `EditionContributor`, `Role`/`Value`/`InstrumentType`, `ParentalWarningStandard` (SoundRecording + Image), optional `ParentalWarningType` (omitted on Release and on the second SoundRecording), `FulfillmentDate`/`FirstPublicationDate` composite (Image), `RightsClaimPolicy`/`RightsClaimPolicyReason` and `PriceInformation` (DealTerms).

New tests: `ParserControllerTest::testSample030..033*`, `testErn43IsNotDetectedAs431`, `SimplifiersTest::testSimpleAlbumErn431`, `testSimpleTrackContributorsErn431`, `testSimpleAlbumErn431RealWorldSingle`, `ParserControllerRulesTest::testRulesPassOnErn431`. `testSample033Ern431NewFeatures` alone carries ~39 assertions, one per new/changed element listed above, each checked against the formal XSD diff in section 2.

## 5. How to test manually

```php
$parser = new \DedexBundle\Controller\ErnParserController();
$parser->setXsdValidation(true);
$ern = $parser->parse('tests/samples/033_ern431_new_features.xml');
echo $parser->getVersion();                       // "431"
get_class($ern);                                  // DedexBundle\Entity\Ern431\NewReleaseMessage
$album = new \DedexBundle\Simplifiers\SimpleAlbum($ern, $parser->getVersion());
$album->getTitle(); $album->getGenre(); $album->getArtists();
$album->getTracksPerCd()[1][1]->getArtistsFromResourceContributors(); // role "AssociatedPerformer"
```

Then try one of your own 4.3.1 files, and a 4.3 file to confirm it is still detected as `43`.

## 6. Known limitations / not done

- Simple entities do not expose the new data (`FormalTitle`, `GroupingTitle`, `ContainsAI`, `Brand`, special contributors, instrument types). It is available on the raw `Ern431` entities.
- Contributors declared with `SpecialContributor` (no party reference) are kept by `getArtistsFromResourceContributors()` but come back with an empty name (`getContributorPartyReference()` is simply absent, so no exception is thrown and no name is resolved).
- `Rule::$supported_versions` still lacks `"42"` (pre-existing, unchanged).
- The samples 030-032 are converted from 4.3 fixtures, not real-world 4.3.1 files. `033` is hand-written to reach every new/changed element; it is not a realistic delivery either (e.g. `Chapter`, `RightsClaimPolicy` and `AdministratingRecordCompany` are combined in one file for coverage, which a real message would not necessarily do together).
